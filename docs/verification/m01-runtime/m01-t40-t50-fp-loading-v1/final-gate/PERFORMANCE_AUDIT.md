**Disposition: no demonstrated performance blocker. Three bounded advisories, ranked below.** This is not task acceptance; verifier and critical reviewer retain that decision.

1. **Advisory, medium: carry framing repeats whole-rig work and creates short-lived math objects every sampled frame.** `src/render/m01-fp-carry.js:9`, `:11-16`, `:20-25`, `:27-44`; caller `src/render/m01-viewmodel.js:261`. There are 20 explicit forced `root.updateMatrixWorld(true)` calls per carry invocation (2 setup, 4 limb solves ×3, 2 carrier arms ×3), in addition to the caller's ordinary matrix update. Both rigs contain dozens of nodes. Each invocation also constructs/clones vectors, quaternions and matrices, allocates the local solver closure and diagnostic arrays/objects, and repeatedly searches bone names. Cost: CPU traversal and garbage collection per changed carry sample, including low quality; it bypasses the existing same-sample early return only when time/state changes. High confidence from control flow; device impact unmeasured. Smallest remedy: retain scratch math objects and bone references on a private carry-frame instance, reuse its diagnostic storage, and update only the modified bone chains between dependent IK steps, retaining a final complete update. Preserve saved-clock sampling and current pose/contact results. Existing unrelated viewmodel allocation patterns are outside this finding.

2. **Advisory, medium: private FP atlas duplicates resident soldier atlas textures.** `src/render/m01-characters.js:39-42`, `:69`; `src/render/m01-viewmodel.js:68-76`. Binary inspection found that the new arms GLB embeds the exact same three image SHA-256 values as `m01_soldier_pl_lod0.glb`: 2048×2048 base color, 1024×1024 normal, 1024×1024 metal/roughness. Separate GLTFLoader parses create separate texture sources; cloned viewmodel materials retain the new source's maps. When both original LOD0 and private FP textures have rendered (high-quality actors, or original fallback rendered before late FP residency), both copies remain owned until character-cache disposal. Cost: duplicate uploads and persistent GPU memory for that mission; approximately 32 MiB for the additional RGBA8+mipmap set is an estimate, not measured renderer memory. High confidence in duplicate image bytes and ownership; conditional GPU residency. Smallest remedy: share the accepted `pl:0` texture slots with private FP atlas materials once both sources exist, keep cache ownership explicit, and avoid uploading private duplicate slots. Do not dispose cache textures from a viewmodel clone. All inspected images are power-of-two and ≤2048²; this is not a texture-size violation.

3. **Advisory, low: native draw diagnostics run continuously and allocate each draw.** `src/render/m01-viewmodel.js:84-97`, `:164`, `:264`, `:272-275`. Two complete weapon-scene traversals install/check hooks on each changed update; one still occurs before a same-sample early return. Native callbacks allocate a fresh mesh array each rendered frame and a row per draw; geometry diagnostics add another traversal/array. Cost: bounded CPU/GC overhead in every preset, even without debug opt-in. High confidence; small bounded scene means no demonstrated blocker. Smallest remedy: install hooks only after build/patient/FX registration changes and reuse fixed draw rows/arrays; optionally collect detailed rows only when requested while retaining honest aggregate native counters.
